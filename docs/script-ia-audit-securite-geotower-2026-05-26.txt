PRIORITE P1 - UPLOAD SIGNALQUEST TROP FACILE A AUTOMATISER
Fichiers principaux:
- docs/server/signalquest_proxy.py
- docs/server/test_signalquest_proxy_security.py
- app/src/main/java/fr/geotower/data/api/SignalQuestApi.kt
- app/src/main/java/fr/geotower/data/workers/SignalQuestUploadWorker.kt

Constat:
Le endpoint /api/v2/signalquest/upload-token emet un jeton HMAC apres seulement un feature flag et un rate limit IP. Un client automatise peut appeler upload-token puis upload. Le HMAC limite le rejeu, mais ne prouve pas que la demande vient d'une instance legitime de l'app.

Travail attendu:
- Ajouter une vraie barriere anti-abus avant emission du token.
- Option recommandee: verifier un jeton Play Integrity cote serveur avant de retourner le token d'upload.
- Alternative acceptable si Play Integrity n'est pas encore branche: rendre les tokens one-shot avec stockage serveur, nonce consomme, quota par site, quota global et rate limit persistant type Redis/DB au lieu d'un dictionnaire memoire.
- L'upload doit refuser un token deja consomme.
- Le token doit rester lie au siteId, a l'IP client et a une expiration courte.
- Ajouter des tests: token valide, token expire, token mauvais site, token mauvaise IP, token rejoue, quota depasse.

PRIORITE P2 - VALIDATION IMAGE COTE SERVEUR
Fichier principal:
- docs/server/signalquest_proxy.py

Constat:
Le proxy accepte un fichier comme JPEG sur la base du Content-Type. Il ecrit le fichier sur disque avant validation forte.

Travail attendu:
- Verifier le contenu reel du fichier comme image JPEG.
- Rejeter les fichiers non images, images corrompues, dimensions excessives et payloads trop gros.
- Idealement reencoder le JPEG cote serveur avant transfert a SignalQuest.
- Continuer a imposer MAX_UPLOAD_BYTES.
- Ajouter des tests unitaires ou d'integration pour: faux JPEG, fichier vide, fichier trop gros, JPEG valide.

PRIORITE P2 - RETENTION DES UPLOADS EN ECHEC
