GeoTower - Deeplinks externes vers les fiches site et support
================================================================

Objectif
--------
Ce document explique comment une application externe peut ouvrir GeoTower
directement sur une fiche particuliere :

- SiteDetailScreen : detail d'un site / antenne / station operateur.
- SupportDetailScreen : detail d'un support / pylone.

L'application GeoTower utilise un schema d'URI custom :

    geotower://

Le package Android de GeoTower est :

    fr.geotower


1. Ouvrir une fiche SiteDetailScreen
------------------------------------

Format public du deeplink :

    geotower://site/{id}

Exemple :

    geotower://site/123456

Cote GeoTower, ce deeplink est mappe vers la route Compose interne :

    site_detail/{id}

Cette route ouvre ensuite SiteDetailToolWrapperScreen, puis SiteDetailScreen.

ID a fournir :

- Idealement, fournir l'identifiant ANFR du site / station, c'est-a-dire id_anfr.
- GeoTower accepte aussi certains identifiants numeriques equivalents, car la
  recherche interne compare aussi les versions numeriques avec ou sans zeros
  en debut d'identifiant.

Exemple Kotlin :

    fun openGeoTowerSite(context: Context, id: String) {
        val uri = Uri.parse("geotower://site/${Uri.encode(id)}")
        val intent = Intent(Intent.ACTION_VIEW, uri).apply {
            addCategory(Intent.CATEGORY_BROWSABLE)
            setPackage("fr.geotower") // Optionnel, mais cible GeoTower directement
        }
        context.startActivity(intent)
    }


2. Ouvrir une fiche SupportDetailScreen
---------------------------------------

Format public du deeplink :

    geotower://support/{id}

Exemple :

    geotower://support/987654

Cote GeoTower, ce deeplink est mappe vers la route Compose interne :

    support_detail/{id}?operator={operator}&fromMap={fromMap}&photoDraftId={photoDraftId}

Mais attention : le deeplink externe actuellement declare est seulement :

    geotower://support/{id}

Donc, pour une application externe, il faut utiliser uniquement ce format simple.

ID a fournir :

- Idealement, fournir l'identifiant du support / pylone, c'est-a-dire id_support.
- L'ID est lu comme une String dans la route, puis converti en Long pour ouvrir
  SupportDetailScreen / SupportSiteWrapperScreen.
- GeoTower peut aussi retrouver les antennes associees a un support via la
  recherche interne.

Exemple Kotlin :

    fun openGeoTowerSupport(context: Context, id: String) {
        val uri = Uri.parse("geotower://support/${Uri.encode(id)}")
        val intent = Intent(Intent.ACTION_VIEW, uri).apply {
            addCategory(Intent.CATEGORY_BROWSABLE)
            setPackage("fr.geotower") // Optionnel, mais cible GeoTower directement
        }
        context.startActivity(intent)
    }


3. Variante avec gestion d'erreur
---------------------------------

Il vaut mieux gerer le cas ou GeoTower n'est pas installe :

    fun openGeoTowerDeeplink(context: Context, uri: Uri) {
        val intent = Intent(Intent.ACTION_VIEW, uri).apply {
            addCategory(Intent.CATEGORY_BROWSABLE)
            setPackage("fr.geotower")
        }

        try {
            context.startActivity(intent)
        } catch (e: ActivityNotFoundException) {
            // GeoTower n'est pas installe, afficher un message ou ouvrir une page de telechargement.
        }
    }

    fun openGeoTowerSite(context: Context, id: String) {
        openGeoTowerDeeplink(context, Uri.parse("geotower://site/${Uri.encode(id)}"))
    }

    fun openGeoTowerSupport(context: Context, id: String) {
        openGeoTowerDeeplink(context, Uri.parse("geotower://support/${Uri.encode(id)}"))
    }


4. Android 11+ et visibilite des packages
-----------------------------------------

Si l'application externe veut verifier si GeoTower est installe avec
PackageManager, elle doit declarer GeoTower dans son AndroidManifest.xml :

    <queries>
        <package android:name="fr.geotower" />
    </queries>

Cette declaration est surtout necessaire pour les appels comme :

    packageManager.getPackageInfo("fr.geotower", 0)
    packageManager.queryIntentActivities(...)
    intent.resolveActivity(packageManager)

Pour simplement appeler startActivity avec setPackage("fr.geotower"), ce n'est
pas toujours indispensable, mais c'est recommande si l'app fait une verification
avant ouverture.


5. Encodage des IDs
-------------------

Toujours encoder l'ID avec Uri.encode(id), surtout si l'identifiant vient d'une
source externe ou peut contenir des caracteres speciaux.

Exemples :

    Uri.parse("geotower://site/${Uri.encode(id)}")
    Uri.parse("geotower://support/${Uri.encode(id)}")


6. Tests rapides avec ADB
-------------------------

Tester l'ouverture d'une fiche site :

    adb shell am start -a android.intent.action.VIEW -d "geotower://site/123456" fr.geotower

Tester l'ouverture d'une fiche support :

    adb shell am start -a android.intent.action.VIEW -d "geotower://support/987654" fr.geotower

Sans forcer le package :

    adb shell am start -a android.intent.action.VIEW -d "geotower://site/123456"
    adb shell am start -a android.intent.action.VIEW -d "geotower://support/987654"


7. Ce qui est declare dans GeoTower
-----------------------------------

Dans AndroidManifest.xml, MainActivity accepte les URI en ACTION_VIEW avec :

    android:scheme="geotower"

Et plus precisement les hosts :

    geotower://site/...
    geotower://support/...

Dans MainActivity.kt, les deeplinks Compose sont :

    navDeepLink { uriPattern = "geotower://site/{id}" }
    navDeepLink { uriPattern = "geotower://support/{id}" }


8. Points d'attention
---------------------

- Les liens web HTTPS ne sont pas declares pour GeoTower a ce stade. Il faut
  utiliser le schema custom geotower://.
- La route radio_site_detail/{stationId}/{supportId} existe en interne, mais
  elle n'est pas exposee en deeplink externe actuellement.
- Pour SupportDetailScreen, les parametres internes operator, fromMap et
  photoDraftId existent dans la route Compose, mais le deeplink externe public
  ne les expose pas officiellement. Utiliser geotower://support/{id}.
- Si plusieurs apps declarent le schema geotower://, Android peut afficher un
  chooser. Utiliser setPackage("fr.geotower") permet de cibler GeoTower.


Resume a transmettre
--------------------

Pour ouvrir GeoTower sur une fiche site :

    geotower://site/{id_anfr}

Pour ouvrir GeoTower sur une fiche support / pylone :

    geotower://support/{id_support}

Package Android cible :

    fr.geotower

Code minimal :

    val uri = Uri.parse("geotower://site/${Uri.encode(id)}")

        addCategory(Intent.CATEGORY_BROWSABLE)
        setPackage("fr.geotower")
