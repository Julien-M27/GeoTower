1. Android Auto HostValidator trop permissif
Fichier:
- app/src/main/java/fr/geotower/services/GeoTowerCarAppService.kt
Zone:
- createHostValidator(), ligne environ 15-17
Probleme:
- Le service exporte retourne HostValidator.ALLOW_ALL_HOSTS_VALIDATOR.
- La documentation AndroidX Car indique que ce validateur est reserve au developpement.
Risque:
- Host non autorise pouvant se connecter au CarAppService.
- Risque securite et risque de rejet Android Auto / Play.
Correction attendue:
- Garder ALLOW_ALL_HOSTS_VALIDATOR uniquement en debug.
- En release, utiliser HostValidator.Builder(this)
  .addAllowedHosts(androidx.car.app.R.array.hosts_allowlist_sample)
  .build()
- Ajouter un commentaire court expliquant debug vs release.
- Verifier que le chemin de fichier est bien services/GeoTowerCarAppService.kt, pas car/.

Fichiers:

Probleme:

3. Widgets: periodic work fragile et annulation globale
Fichiers:
- app/src/main/java/fr/geotower/widget/AntennaWidgetReceiver.kt
- app/src/main/java/fr/geotower/widget/AntennaWidgetMediumReceiver.kt
- app/src/main/java/fr/geotower/widget/AntennaWidgetLargeReceiver.kt
- app/src/main/java/fr/geotower/widget/AntennaMapWidgetReceiver.kt
Zones:
- lecture widget_sync_freq
- PeriodicWorkRequestBuilder
- cancelUniqueWork("WidgetPeriodicUpdate")
Problemes:
- Si une ancienne preference widget_sync_freq est inferieure a 15 minutes, WorkManager peut lever une IllegalArgumentException.
- Les 4 receivers utilisent le meme unique work name "WidgetPeriodicUpdate".
- onDisabled annule le work global meme si un autre type de widget existe encore.
Correction attendue:
- Centraliser la planification dans un WidgetUpdateScheduler.
- Clamper la frequence: au minimum 15 minutes, idealement garder 30 minutes comme valeur UI actuelle.
- Ne faire cancelUniqueWork que si plus aucun widget GeoTower n'est actif.
- Ajouter tests unitaires pour le clamp et la logique "cancel only when no widgets".

Exemple attendu:
val freqMinutes = prefs.getInt("widget_sync_freq", 60)
    .coerceAtLeast(30)
    .toLong()

4. CompassScreen: appels LocationManager non proteges
Fichier:

Zones:
- registerListener avec rotationSensor potentiellement null
- getLastKnownLocation GPS/NETWORK
- requestLocationUpdates GPS/NETWORK
Probleme:
- Peut crasher si provider absent/desactive, permission revoke, GPS off, ROM OEM stricte.
Correction attendue:

- NETWORK peut fonctionner avec coarse.
- Ajouter tests si la logique est extraite, sinon au minimum verifier manuellement: GPS off, permission refusee, permission precise vs approximative.

5. Foreground service location: start non protege Android 12+
Fichiers:
- app/src/main/java/fr/geotower/services/LiveTrackingController.kt
- app/src/main/java/fr/geotower/services/LiveTrackingService.kt
Probleme:
- startForegroundService est appele sans try/catch.
- Android 12+ peut lever ForegroundServiceStartNotAllowedException.
- Android 14+ applique les restrictions while-in-use pour les FGS location.
Correction attendue:
- Utiliser ContextCompat.startForegroundService si pertinent.
- Catcher ForegroundServiceStartNotAllowedException, SecurityException, IllegalStateException.
- Ne lancer le service que depuis un parcours utilisateur visible ou une exemption valide.
- Si lancement depuis background, verifier ACCESS_BACKGROUND_LOCATION sur Android 10+.
- Conserver foregroundServiceType="location" et permissions manifest existantes.
- Documenter le parcours pour Play Console.

6. Workers longs: ne pas continuer si setForeground echoue
Fichiers:
- app/src/main/java/fr/geotower/data/workers/MapDownloadWorker.kt
- app/src/main/java/fr/geotower/data/workers/SignalQuestUploadWorker.kt
Probleme:
- Si setForeground echoue, le worker continue un transfert long en background.
- Sur Android 14/15/16 et ROM OEM, risque kill, retry incoherent, batterie, UX invisible.
Correction attendue:
- Pour les transferts longs, retourner Result.retry() ou Result.failure() si foreground impossible.
- Ne pas masquer l'echec par une notification classique.
- Ajouter contraintes reseau au MapDownloadWorker depuis MapDownloadCard.
- Garder la validation SHA256 des cartes.

7. Background location Android 11+ et Play policy
Fichier:
- app/src/main/java/fr/geotower/ui/screens/settings/SettingsScreen.kt
Zone:
- bloc ACCESS_BACKGROUND_LOCATION, autour des lignes 2178-2231
Probleme:
- Sur Android 11+, le dialogue runtime ne propose pas "Allow all the time"; l'utilisateur doit passer par les parametres.
- Play exige une justification claire si ACCESS_BACKGROUND_LOCATION est declaree.
Correction attendue:
- Demander foreground location d'abord.
- Pour Android 10, RequestPermission(ACCESS_BACKGROUND_LOCATION) peut etre utilise.
- Pour Android 11+, afficher une UI educative claire puis ouvrir les parametres de l'app / page permission location.
- Utiliser getBackgroundPermissionOptionLabel() si disponible pour label localise.
- L'utilisateur doit pouvoir refuser et continuer a utiliser l'app.
